# DeepSeek-Prover — 通过 RL 与 MCTS 实现形式化定理证明

- **作者 / 机构**：DeepSeek-AI（Xin 等）
- **发表时间**：2024-05（V1，arXiv:2405.14333）；2024-08（V1.5，arXiv:2408.08152）
- **链接**：[V1 论文 (arXiv:2405.14333)](https://arxiv.org/abs/2405.14333) · [V1.5 论文 (arXiv:2408.08152)](https://arxiv.org/abs/2408.08152) · [代码 (V1.5)](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5)

## 一句话总结

DeepSeek-Prover 将 LLM 微调和强化学习应用于 **Lean 4 形式化定理证明**。核心 infra 洞察：Lean 4 编译器是一个**完美的二元 oracle**——它能确定性地判断证明是否正确，无需人工标注，无需奖励模型。这使形式化定理证明成为数学推理最纯粹的 RL 环境：奖励即真值，步骤级验证免费（只需类型检查策略），问题空间（Mathlib4）包含数万道难度递增的定理。V1 通过将非形式化数学翻译为 Lean 4 并以编译器过滤来生成合成训练数据。V1.5 增加了基于 **RMaxTS**（奖励最大树搜索）的强化学习——一种将探索集中在最有前途证明分支上的蒙特卡洛树搜索变体。DeepSeek-Prover-V1.5 在开源模型中达到 miniF2F-test 最优水平，更重要的是，它具体实例化了 R1/GRPO 抽象描述的推理时扩展和 PRM 思想。

## 背景与动机

### 形式化定理证明为何与 AI infra 相关

Lean 4、Coq 或 Isabelle 等系统的形式化定理证明要求产出机器可验证的证明：每一个逻辑步骤都必须表达为类型检查器接受的**策略（tactic）**。这与非形式化数学（由人类判断推理是否有说服力）和代码生成（测试检查输出而非证明结构）有本质区别。

对 LLM 而言，这创造了一个异常简洁的 RL 问题：

1. **二元精确奖励**：Lean 4 编译器要么接受证明，要么拒绝，没有人类偏好，没有学习型 RM，没有奖励信号的分布偏移。
2. **步骤级验证免费**：Lean 4 证明中的每个策略都可以单独进行类型检查。一个到第 k 步有效、第 k+1 步无效的部分证明可以立即定位——编译器精确告诉你失败在哪里。这是免费的 PRM。
3. **无限量问题供应与难度梯度**：Mathlib4（主要的 Lean 4 数学库）包含 15 万余条定理，从本科水平到研究前沿。在该库上进行课程学习是自然的。
4. **无数据污染**：Lean 4 形式化证明在典型 LLM 预训练数据中大规模存在的可能性极低；性能提升不太可能是记忆伪影。

与更广泛推理议程的联系：如果 GRPO + 规则奖励可以让模型在非形式化数学上推理（R1），那么同样的方法——用编译器替代符号检验器——能否让模型产出**可验证正确**的数学推理？

### V1 解决的缺口

2024 年之前，前沿 LLM 能生成非形式化数学论证，但无法为非平凡定理可靠地产出有效的 Lean 4 证明。瓶颈在于训练数据：Lean 4 证明在网络爬取中稀少，而人工编写 Lean 证明需要数学专家。V1 的假设：以编译器过滤的**自动形式化**（非形式化数学 → Lean 4 翻译）可以从现有的非形式化数学语料库中生成足够的训练数据。

## 核心方法

### V1：自动形式化与数据合成

V1 流程：

1. **非形式化来源**：从网络来源和 benchmark（MATH、AMC、AIME 等）收集有已知解法的高中和奥数题。

2. **自动形式化**：提示基础 LLM 将每道非形式化问题 + 解题过程翻译为 Lean 4 定理陈述和证明草稿。翻译不完美，经常出错。

3. **编译器过滤**：对每个生成的证明运行 Lean 4 编译器。仅接受完全通过编译（类型检查）的证明。拒绝率很高（约 95%），但在规模上，即使数百万生成证明中的 5% 也能产出数十万条有效训练样本。

4. **在有效证明上 SFT**：使用标准 next-token prediction 在接受的（问题、证明）对上微调模型。编译器过滤步骤确保训练数据无噪声——SFT 集中的每个样本都是经过验证的正确证明。

5. **迭代精化**：用微调后的模型（更擅长产出有效 Lean 4）重新运行自动形式化，再次过滤，循环往复。每次迭代生成更难的有效证明。

核心洞察：**编译器在每个阶段替代了人工标注**。无需数学家验证训练样本；类型检查器自动、大规模地完成这一工作。

### V1.5：基于蒙特卡洛树搜索的 RL

V1.5 在 V1 的 SFT checkpoint 之上增加了一个强化学习阶段，以证明搜索作为 RL 环境。

#### 将证明搜索建模为 MDP

形式化证明是一个策略序列 `t₁, t₂, ..., tₖ`，将初始目标转化为完整证明。每个策略以当前**证明状态**（剩余目标和假设）为输入，产出新的证明状态。这是一个马尔可夫决策过程：

- **状态**：当前证明状态（表示剩余目标的结构化 Lean 4 项）
- **动作**：下一个策略（LLM 生成的 token 序列）
- **奖励**：证明完成（所有目标关闭）时 +1，否则为 0
- **终止**：证明完成，或达到最大深度 / 超时

LLM 是策略：以证明状态为上下文，生成下一个策略。Lean 4 类型检查器是环境：应用策略、检查，并返回新的证明状态或失败信号。

#### RMaxTS

标准 MCTS 使用节点回滚的**平均**奖励估计其价值。对于定理证明，这低估了稀有但有效证明路径上节点的价值：在 10 次回滚中导向 1 次成功证明的节点远优于导向 10 次失败证明的节点，但在噪声设置下，它们的平均奖励（0.1 vs 0）差距甚微。

RMaxTS 将价值估计修改为任意回滚的**最大**奖励：

```
V_RMax(节点) = max(所有经过该节点的回滚奖励)
```

UCT 选择公式变为：

```
score(节点) = V_RMax(节点) + c · √(ln N_父节点 / N_节点)
```

其中 `c` 控制探索。最大价值备份有两个推论：

1. **单次成功回滚将子树标记为高价值**，无论此前有多少次失败回滚，后续探索都会被引导至该子树。
2. **稀有的有效证明路径不会被多数无效路径淹没**——最大值在大多数回滚失败时也能保留。

这非常适合定理证明，因为有效证明稀疏（大多数随机策略序列失败），但一旦部分证明路径成功，搜索应该大力投入。

#### 整体证明生成与逐步生成的结合

V1.5 使用两种互补的生成模式：

- **整体证明生成**：将整个证明作为单一 token 序列生成，然后编译。速度快；每次尝试一次 LLM 调用；对于长证明，链深处的错误会使整个证明失效，失败无声。

- **带 MCTS 的逐步生成**：每次生成一个策略，用编译器检查每一步，将每步之后的证明状态作为下一步上下文。MCTS 协调扩展哪些部分证明。每道定理更慢，但对证明空间的探索更系统。

实践中，V1.5 对较简单的定理使用整体证明生成（更快、开销更低），对整体生成反复失败的定理使用 MCTS。

#### RL 训练循环

训练循环在搜索与学习之间交替：

1. **回滚阶段**：对一批定理运行 RMaxTS，生成证明尝试轨迹。
2. **奖励分配**：Lean 4 编译器对完整轨迹分配二元奖励。
3. **策略更新**：对成功轨迹（正奖励）相对于尝试组使用 GRPO 更新 LLM。失败尝试提供负基线。
4. **循环**：改进后的策略在下一个回滚阶段生成更好的证明尝试。

Lean 4 编译器是唯一的奖励来源——无人工标注，无学习型 RM。编译器同时扮演奖励模型和步骤级验证器（PRM）。

### Lean 4 基础设施要求

运行此训练循环需要 Lean 4 工具链作为 LLM 的协同进程：

- **Lean 4 + Mathlib4**：必须安装并可加载；Mathlib4 从头编译需约 30 分钟，但可缓存。
- **LeanDojo**（Yang 等，2023）：封装 Lean 4 的 Python 接口，以编程方式提取证明状态并交互式应用策略。V1.5 的逐步 MCTS 环境依赖 LeanDojo。
- **并行性**：每道定理搜索相互独立；并行运行 256 或 1024 道定理搜索需要 256–1024 个并发 Lean 4 进程，每个进程都加载了 Mathlib4 环境。每进程内存约 2–4 GB。典型的训练服务器配备 8 张 H100，GPU 运行 LLM 推理，CPU 运行 Lean 4 验证。
- **延迟**：Lean 4 类型检查器对单个策略速度很快（每步 1–50 ms），但加载每道新定理的完整 Mathlib4 上下文需要 2–5 秒。跨 MCTS 回滚缓存每道定理的 Lean 环境对吞吐至关重要。

## 工程权衡

| 决策 | 得到什么 | 放弃什么 |
|---|---|---|
| Lean 4 编译器作为奖励 | 完美二元奖励；无 RM 训练；无奖励黑客 | 需要 Lean 4 工具链基础设施；将领域限制为可形式化表达的数学；RL 循环中的编译延迟 |
| 自动形式化 + 过滤（V1） | 从非形式化数学获取可扩展训练数据；无需人工标注 | 约 95% 拒绝率在规模上成本高昂；翻译质量限制了哪些非形式化证明可被正确形式化 |
| RMaxTS（最大奖励备份） | 稀疏有效证明在多数无效回滚中存活；困难定理收敛更快 | 对许多路径都成功的简单问题不如均值备份稳定；超参数 c 较敏感 |
| 整体 vs 逐步生成 | 整体生成快；逐步生成支持 MCTS 搜索 | 必须按定理选择模式或同时运行两者；逐步需要 LeanDojo 集成和逐步编译器调用 |
| 用 GRPO 更新策略 | 无 critic 模型；与 R1 训练相同的基础设施；来自证明结果的组相对优势 | 证明奖励是二元的（0/1），不分等级；所有回滚失败或成功时 GRPO 优势归零——探索需要非平凡的 pass@k |
| Mathlib4 作为训练领域 | 从本科到研究水平的难度梯度；定理多样 | Lean 4 + Mathlib4 是特定的形式系统；不重新训练无法推广到 Coq/Isabelle/HOL |

## 实验与结果

**miniF2F benchmark**（Lean 4/Isabelle 形式化的高中奥数题；244 道测试定理）：
- DeepSeek-Prover-V1（整体证明）：46.3% pass@32（每道定理尝试 32 次）
- DeepSeek-Prover-V1.5（整体证明）：48.2% pass@32
- DeepSeek-Prover-V1.5（RMaxTS，600 次回滚）：**63.5% pass@32**——增加树搜索后的大幅提升

对比：
- GPT-4（仅非形式化推理，无 Lean）：非形式化 miniF2F 约 50%，但无法产出有效 Lean 证明
- InternLM2-Math-Plus 7B（此前开源最优）：Lean 4 上 miniF2F 约 43%

**FIMO benchmark**（IMO 难度的竞赛数学）：
- V1.5 解出 5/148 道——绝对数量不多，但开源 7B 级模型在 IMO 难度问题上得到非零分数值得注意。

**随搜索预算扩展**：从 64 到 600 次 RMaxTS 回滚，miniF2F 通过率呈对数线性增长，证实了推理时计算量扩展适用于形式化证明搜索。

## 可复现性说明

- V1.5 代码、权重和形式化定理数据集已在 [github.com/deepseek-ai/DeepSeek-Prover-V1.5](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5) 发布。
- **LeanDojo** 需单独安装：`pip install lean-dojo`。需要 Lean 4 和 Mathlib4；首次 Mathlib4 构建需 20–40 分钟。
- **复现 RL 循环**：训练代码已发布。关键要求：配备足够 CPU 以并行运行多个 Lean 4 进程的机器（建议 ≥64 CPU 核以获得合理吞吐）。每次 RMaxTS 回滚在搜索期间占用一个 CPU 核。
- **评估**：已发布的模型可用提供的脚本在 miniF2F 上评估；评估本身需要 Lean 4 + Mathlib4，在单机上对完整 244 道测试题集评估需数小时。
- **自动形式化流程**（V1）也已发布；需要有能力进行非形式化 → Lean 翻译的 LLM，可用 DeepSeek-Prover 模型本身以自举方式完成。

## 评注

DeepSeek-Prover 是本仓库中将推理时扩展论点应用于非平凡领域最清晰的具体案例。[推理时扩展条目](../../foundational/inference-time-scaling/)将带验证器的并行搜索描述为一般模式；Prover 展示了当验证器是类型检查器、搜索空间是有效 Lean 4 策略序列集合时的具体面貌。

三个值得明确指出的与其他条目的联系：

**编译器作为完美 PRM。**[PRM 条目](../../foundational/process-reward-models/)解释了人工标注训练 PRM 的成本高昂且特定于领域，MC 回滚标注是一种近似。Lean 4 绕过了这两个问题：每次策略应用都是免费、精确的步骤级验证。编译器就是 PRM 社区试图为非形式化数学近似的那个 PRM。

**无奖励模型的 GRPO。** 训练循环使用带二元编译器反馈的 GRPO——无 RM，无人类偏好数据。这是 R1-Zero 的形式化数学类比，其原理相同：奖励是真值且无歧义。区别在于 R1-Zero 的"验证器"是符号答案检查器（比较数值输出），而 Prover 的验证器是验证逻辑结构的完整类型检查器。

**RMaxTS 与稀疏奖励问题。**[推理时扩展条目](../../foundational/inference-time-scaling/)讨论了 MCTS 作为搜索策略，并提到 PRM 提供即时价值估计。当奖励稀疏且二元时，RMaxTS 是正确的 MCTS 变体：哪怕只有一次回滚成功，该节点也值得进一步探索，无论有多少次失败。均值备份 MCTS 会低估百分之一成功率的节点价值；RMaxTS 正确地将其识别为高价值节点。这是一个在任何奖励信号稀疏且精确的场景下都适用的设计原则。

局限性是真实存在的：形式化证明要求将问题表达为 Lean 4，这对大多数数学来说是很高的门槛。模型无法对尚未被形式化的问题进行推理，而形式化本身就是瓶颈。长期问题是：形式化证明能力是否会迁移到非形式化推理——在 Lean 4 有效证明上训练的模型，与仅在非形式化数学上训练的模型相比，是否在非形式化多步数学上更出色？早期证据表明是的（DeepSeek-Prover 模型在非形式化 MATH benchmark 上也表现良好），但这是一个活跃的研究问题。
