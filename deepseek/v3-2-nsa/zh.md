# DeepSeek V3.2 — 原生稀疏注意力（NSA / DSA）

- **作者 / 机构**：DeepSeek-AI
- **发表时间**：2025-09（实验性发布）
- **链接**：[DeepSeek-V3.2-Exp (GitHub)](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp) · [DeepGEMM V3.2 索引核（PR #200）](https://github.com/deepseek-ai/DeepGEMM)

## 一句话总结

DeepSeek V3.2 在 671B V3 MoE 底座的基础上，将标准全量注意力替换为**原生稀疏注意力（NSA，DeepGEMM 代码库中称为 DSA）**。核心变化：每个注意力层并行运行三条子计算路径——压缩全局路径、学习稀疏选择路径、局部滑动窗口路径——三路输出通过逐头标量权重加权合并。在 128k 上下文下，选择路径每次查询只需关注约 1024 个 token（k=16 个块，每块 64 token），相比全量注意力每层注意力显存减少约四个数量级，同时在长上下文 benchmark 上实现接近无损的质量表现。本文档补全了 V3 技术报告与 DeepGEMM 源码走读中都提及 V3.2 索引核却未解释其架构机制的缺口。

## 背景与动机

V3 底座架构已经解决了长上下文三大瓶颈中的两个：

1. **KV 缓存大小**：MLA 在**头维度**压缩 KV 缓存——推理阶段每 token 缓存大小约为标准 MHA 的 1/10。详见 `../mla/`。
2. **序列并行开销**：Ring Attention（见 `../../foundational/ring-attention/`）将序列分布到多设备，使每台 GPU 的激活显存保持常量。V3 在 128k 上下文扩展阶段使用了该技术。
3. **单设备注意力计算与显存**：在 S=128k 时，即使有 FlashAttention 的 IO 优化，全量注意力的 O(S²·d) 开销依然主导计算量。这正是 NSA 填补的空缺。

单层注意力矩阵显存的量级可以直接计算：

$$
\text{注意力矩阵显存} = S^2 \cdot n_\text{heads} \cdot 2\;\text{字节（BF16）}
$$

以 S=128k、n_heads=128 为例：128000² × 128 × 2 ≈ **4.3 TB / 层**。即使 FlashAttention 的分块执行避免了完整矩阵的物化，单层 forward 中必须经过 HBM 的有效工作集仍远超任何单 GPU 的 HBM 容量（H100 为 80 GB）。序列并行将其除以 CP 份数，但每个 rank 每层仍需支付 O((S/P)²) 的计算量。将注意力开销从 O(S²) 降到 O(S) 的唯一办法是让每次查询只关注更少的 token——而这要求选择过程足够智能，不损失模型质量。

此前已有多年的近似稀疏注意力研究（Longformer、BigBird、固定局部窗口），但它们要么使用无法捕获任务特定相关性的固定模式，要么需要与模型分离训练的独立检索系统。NSA 的设计目标是**可学习的、与模型主损失端到端联合训练的稀疏选择**，且模式可随查询自适应调整。

## NSA 架构：三条并行路径

每个 NSA 注意力层对同一组查询计算三个子注意力，输出加权求和：

```
Output = w_c · Attn_compressed(Q, KV_compressed)
       + w_s · Attn_selected(Q, KV_selected)
       + w_w · Attn_window(Q, KV_local)
```

每头标量权重 `(w_c, w_s, w_w)` 经过学习，在三路输出合并时应用。这不是硬性切换——三条路径同时激活；模型可以学习在检索密集型查询上放大选择路径权重，在局部连贯文本上放大窗口路径权重。

### 路径一——压缩路径（粗粒度全局上下文）

将整个 KV 序列切分成固定大小的块。对每个块，**一个学习到的线性投影**将块内所有键向量映射为单一代表键（值向量同理）。块大小 B=64、序列长度 S=128k 时，产生 2000 个代表 KV 对——对序列的粗粒度但全局的汇总。

压缩路径将查询 Q 与这 2000 个代表键做注意力。代价：每头 O(S/B)，约 O(2000)——相对于 S 几乎是常量。该路径提供低频全局信号：主题、长程依赖、非常早期的上下文。投影权重经过训练，模型可以学习如何进行最优汇总。

显存：每层每条序列 2 × (S/B) × d_head × 2 字节 = 2 × 2000 × 128 × 2 ≈ **1 MB**，可忽略不计。

### 路径二——选择路径（细粒度稀疏检索）

这是机制上最有趣的路径。在计算注意力之前，**轻量门控网络**对每个键块相对于当前查询打分，选出 top-k 个块。DeepSeek 使用 k=16 个块 × 64 token = 1024 个 token/查询。块 j 对查询 i 的门控评分为：

$$
g_{ij} = \text{ReLU}\!\left(\sum_{h} \mathbf{q}_i^{(h)} \cdot \mathbf{k}_j^{(h)}\right) \cdot w_i
$$

其中求和跨头进行，`k_j` 是该块的代表键（与压缩路径使用同一个），`w_i` 为可学习的逐查询权重向量，输出为标量相关性评分。按评分取 top-k 块索引，传入稀疏注意力核。

这正是 DeepGEMM 词条中所称的 **V3.2 Lightning Indexer**：`fp8_mqa_logits` 和 `fp8_paged_mqa_logits` 核精确实现了这一评分。核的形状为 `[Q_tokens, n_heads, d_head] × [KV_blocks, d_head]`，尾声融合 ReLU 加权求和——这是一个窄 GEMM（K/N 很大，M 很小），每个（查询，块）对输出一个标量。

确定 top-k 块后，**V3.2 索引核**将稀疏块索引物化为紧凑的 (query_idx, key_block_idx) 对列表。DeepGEMM 的 `m_grouped_fp8_gemm_*` 核将每个选中块的注意力作为分组 GEMM 分发执行——与 V3 训练中处理专家分发的 MoE 布局分组 GEMM 完全相同。这正是 NSA 与 DeepGEMM 紧密耦合的架构原因：MoE 分组基础设施已经存在；NSA 的块选择复用了相同的分发机制。

选择路径的注意力显存：k × B × d_head × n_heads × 2 字节 = 16 × 64 × 128 × 128 × 2 ≈ **34 MB / 层**——而全量注意力约 4.3 TB。减少约 13 万倍。

注意力计算量：每头每查询 O(k·B·d_head) = O(1024 × 128) = O(131k)，而全量注意力为 O(128k × 128) = O(16M)，约减少 120 倍。

### 路径三——窗口路径（局部连贯性）

对最近 w 个 token（通常 w=512～1024）做标准因果滑动窗口注意力。无选择，无门控。该路径处理局部句法连贯性、句子级上下文和近期状态——这些场景天然需要邻近性，无需学习。路径代价为 O(w)/查询，与总序列长度无关。

FlashAttention 的分块核在此直接使用，无需修改；窗口掩码作为 FA2 已支持的标准因果加窗口掩码模式应用。

## V3.2 索引核：核级视角

`fp8_mqa_logits` 核位于 DeepGEMM 仓库 `csrc/jit_kernels/impls/smxx_fp8_mqa_logits.hpp`（PR #200 新增）。其职责：

1. **预填充（非分页）**：`Q ∈ [T_q, n_h, d_h]` × `KV ∈ [T_kv, d_h]` → 块级池化与 ReLU 加权求和后得到 `logits ∈ [T_q, n_h, T_blocks]`。KV 在显存中连续存储。

2. **解码（分页）**：`fp8_paged_mqa_logits` 处理分页 KV 缓存场景，KV 块可能不连续。分页变体在打分前通过块表 (block table) 收集所需的键块。

两种情况下，输出均为每查询每头对应每个 KV 块的标量相关性值。top-k 选择在 Python / 主机端对这个小矩阵（`T_q × N_blocks`）执行，结果稀疏索引列表回传给分组 GEMM 核执行实际注意力计算。

评分函数中的 ReLU 并非偶然——它使明显无关块的得分严格为零（硬排除），而不仅仅是得分很小。同时使门控函数非负，权重 `w_i` 可解释为注意力幅度而不存在抵消现象。

## 训练注意事项

### 块选择的可微性

Top-k 选择在标准意义上不可微：评分中细微变化导致某块进出 top-k 时，输出发生不连续跳变。常见两种处理方式：

- **直通估计器（STE）**：前向使用硬 top-k；反向将选择视为软操作传递梯度（等效于所有块都被选中时的梯度）。实现简单，但引入梯度噪声。
- **Gumbel-Softmax 松弛**：用带温度参数的 softmax 替代硬选择，训练过程中退火趋向硬选择。全程可微；计算代价更高。

V3.2 采用带辅助损失的 STE 形式来管理梯度质量。门控函数（即 `fp8_mqa_logits` 评分）只通过被选中的块接收梯度，未被选中的块无法得到其评分应如何调整的信号。若不加干预，将导致路由坍缩——少数块永久被选中。

### 负载均衡：稀疏路由的 MoE 类比

该问题与 MoE 专家负载均衡完全对应（见 `../v3-tech-report/`）。V3.2 引入**辅助覆盖损失**：

$$
\mathcal{L}_\text{cover} = \lambda \sum_j \left( f_j - \frac{1}{N_\text{blocks}} \right)^2
$$

其中 `f_j` 为块 j 被选中的实际比例。该损失惩罚选择集中于少数"常驻"块（通常是序列开头的 BOS 上下文或尾部近期窗口）。若无此损失，首尾块倾向于垄断选择，中间块几乎从不被训练。

`λ` 系数是重要超参数：过大则强迫均匀选择，破坏相关性信号；过小则坍缩重现。V3.2 报告从零开始训练 NSA，避免了在预训练稠密模型上改造时重新学习注意力模式的问题。

### 从头训练与改造预训练模型

从头训练 NSA 远比改造预训练稠密模型干净。预训练稠密模型以假设全量注意力的方式将信息分布到所有注意力位置；引入稀疏性会切断大量信息通路，需要完全重新学习。V3.2 的做法——从第一个训练步骤即使用稀疏注意力——意味着模型永远不会学习依赖之后会被掩掉的位置。

代价：前约 1000 亿训练 token 对模型更难，因为稀疏注意力每步提供的信号更少。实践中 V3.2 通过对覆盖损失 `λ` 使用预热调度、以及在窗口路径初期使用更宽的窗口来弥补。

## 显存与计算汇总

| 路径 | 每查询关注 token 数 | 注意力显存（每层，S=128k） | 每头注意力算力 |
|---|---|---|---|
| 全量注意力（基准） | 128,000 | ~4.3 TB | O(16.4M) |
| 压缩路径 | ~2,000 (S/B) | ~1 MB | O(256k) |
| 选择路径（k=16, B=64） | 1,024 | ~34 MB | O(131k) |
| 窗口路径（w=512） | 512 | ~17 MB | O(65k) |
| NSA 合计 | ~3,536 | ~52 MB | ~O(450k) |

NSA 合计约为全量注意力 **1/83 的注意力显存**，且该比例随序列长度增长：S=256k 时约为 1/330，因为全量注意力是二次增长，而 NSA 选择路径以 k·B（固定）为主、压缩路径以 S/B（线性）为辅。

索引核本身有额外开销：每层每头需对 `T_q × N_blocks` = `128k × 2000` 个评分做矩阵乘。这是一个大规模矩阵乘，但在 FP8 精度下且深度融合；DeepGEMM 的 `fp8_mqa_logits` 核被设计为带宽受限而非算力受限，其代价远低于主注意力计算。

## 与其他稀疏注意力方案的对比

| 方案 | 优势 | 劣势 | 适用场景 |
|---|---|---|---|
| **NSA（V3.2）** | 可学习，端到端训练；在选中块内复用 FlashAttention；支持分页 KV 与 FP8 | 训练复杂（梯度、负载均衡）；需要定制索引 CUDA 核；三路架构增加代码维护面 | 从头训练的长上下文 MoE 模型；任务分布足够一致使门控能有效学习时 |
| **Longformer / BigBird（固定模式）** | 实现简单；无额外训练开销；显存模式可预测 | 模式不随任务自适应；全局 token（CLS、SEP）固定非学习；检索密集型任务质量下降明显 | 具有明确局部+全局结构的应用（文档分类、固定 schema QA） |
| **FlashAttention（稠密+IO 优化）** | 精确无近似；适用所有任务；广泛可用 | O(S²) 算力与显存；无序列并行时无法扩展到 128k+ | S ≤ 32k 或有强 CP 支撑；需要每个位置均精确关注时 |
| **仅滑动窗口** | 实现极简；O(S·w) 显存 | 无长程检索；完全缺失跨文档依赖 | 近期上下文主导的文本生成（续写、流式生成） |
| **Ring Attention（序列并行）** | 精确；显存随设备数线性分摊；与其他技术正交 | 单条序列也需多 GPU；延迟受环形通信约束；单设备仍是 O(S²/P) 二次增长 | 多 GPU 服务或训练中可接受按序列增设备的场景；与 NSA 互补（外层并行 + 内层稀疏） |

## 实验结果

V3.2 报告在 RULER（测试检索、追踪、推理的长上下文合成 benchmark）和 LongBench（真实长文档 QA 与摘要）上相比全量注意力基准实现接近无损的质量。核心结论：

- **困惑度**在 4k 到 128k 各上下文长度上与全量注意力相差 0.1～0.2 nats 以内。
- **RULER**：选择性检索与多跳任务是固定模式稀疏方法最难处理的场景，V3.2 的 NSA 在这些任务上几乎无退化，验证了学习门控能正确定位相关块。
- **128k 原生上下文**，无需 RoPE 插值。全量注意力版的 V3 使用扩展基频 RoPE（YaRN 风格）达到 128k；V3.2 的选择路径每次只在 1024 个 token 内做注意力，该路径的查询与键之间的位置 ID 差距永远不超过 1024，消除了主算力路径上的位置编码压力。

覆盖辅助损失对以上结果至关重要——不加该损失的早期消融实验在多跳任务上 RULER 退化 3～5 分，恰好是块覆盖度最关键的场景。

## 个人评注

NSA 是 DeepSeek 长上下文技术栈中继 MLA 与 Ring Attention 之后的第三根支柱。三者各自作用于注意力张量 `S × n_heads × d_head` 的不同维度：MLA 压缩 d_head，NSA 压缩 S，Ring 分布 S/P。NSA 之所以具有产业意义而不仅停留在学术层面，关键在于核级协同设计——V3.2 索引核不是玩具式评分机制，而是一个集成在与 V3 MoE 分发相同的分组 GEMM 基础设施之上的生产级 FP8 核。将 NSA 构建在 MoE 分发机制之上而非重新实现稀疏注意力核，这种系统直觉在论文中容易忽视，但在读 DeepGEMM 的 PR 时立刻显而易见。

负载均衡问题同样值得认真对待：与 MoE 路由坍缩的类比不只是表面相似。两者本质相同——可学习的离散选择在不可微 top-k 下，没有显式正则化就必然坍缩到小吸引子集合。NSA 的辅助覆盖损失与 V3 无辅助损失 MoE 均衡中的逐专家偏置项扮演相同角色——两者都是让训练后的模型真正使用你设计进去的容量所必须付出的代价。
