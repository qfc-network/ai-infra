# CLIP — 对比语言-图像预训练

- **作者 / 机构**：Alec Radford、Jong Wook Kim、Chris Hallacy、Aditya Ramesh 等（OpenAI）
- **发表时间**：2021-02-26
- **链接**：[arXiv:2103.00020](https://arxiv.org/abs/2103.00020) · [博客](https://openai.com/research/clip) · [代码](https://github.com/openai/CLIP)

## 一句话总结

CLIP 在 4 亿张从网络爬取的图文对上，通过对比学习目标联合训练图像编码器和文本编码器。推理时，零样本分类通过计算类别文本描述与图像嵌入之间的余弦相似度完成，无需任何 ImageNet 训练标签便能达到或超越有监督基线。CLIP 证明了网络规模的弱监督对比学习具有极强的泛化能力，并成为视觉语言模型和 RLHF 奖励建模的事实标准视觉骨干。

## 背景与动机

CLIP 之前，视觉模型依赖精心标注的数据集（ImageNet、COCO）。这造成双重瓶颈：标注成本高昂，固定标签空间使模型无法对新任务做零样本迁移。NLP 领域早已通过在原始网络文本上自监督预训练解决了类似问题——CLIP 的核心洞察是将同样的思路应用于视觉，把互联网上天然存在的图文对作为免费的监督信号。

同期的弱监督视觉工作（ALIGN、ConVIRT）也探索了类似方向。CLIP 的贡献在于规模：4 亿图文对、简洁的对比目标，以及在 30 个数据集上全面的零样本评测。所得嵌入的泛化能力极强，几乎所有后续视觉语言模型都以 CLIP 特征为骨干，包括 [LLaVA](../llava/zh.md) 和 [Llama 4](../../meta/llama4/zh.md)。

## 架构设计

### 双编码器结构

CLIP 使用两个独立编码器：

**图像编码器**：ResNet（带注意力池化）或视觉 Transformer（[ViT](../vit/zh.md)）。公开的最佳模型使用 ViT-L/14——patch 尺寸 14px，在 336px 分辨率下微调。编码器为每张图像输出单一固定维度向量（如 ViT-L 为 768 维）。

**文本编码器**：带因果掩码的 Transformer，对 BPE 分词后的文本序列进行编码，取 `[EOS]` 位置的表示作为文本嵌入，并通过线性层投影到共享嵌入空间。

两个编码器的输出在计算相似度之前均做 L2 归一化。关键设计原则：两个塔不共享权重，也不设交叉注意力——模态间的唯一交互发生在对比损失函数中。

### 对比 InfoNCE 损失

对于一批 N 个图文对，CLIP 构造 N×N 相似度矩阵：

$$S_{ij} = \frac{\text{img}_i \cdot \text{txt}_j}{\tau}$$

其中 τ 是可学习的温度参数。损失将 N 个正确配对（对角线元素）作为正样本，N²−N 个非对角线元素作为负样本：

$$\mathcal{L} = -\frac{1}{2N} \sum_{i=1}^{N} \left[ \log \frac{e^{S_{ii}}}{\sum_j e^{S_{ij}}} + \log \frac{e^{S_{ii}}}{\sum_j e^{S_{ji}}} \right]$$

两项分别对应图像→文本和文本→图像方向的对称损失，即 InfoNCE（噪声对比估计），也称 NT-Xent。

**温度参数 τ**：CLIP 将 τ 作为对数尺度参数学习，初始值为 0.07。温度控制分布的锐利程度：低温使 softmax 更尖锐，相当于更难的负样本。在大批量（CLIP 最大使用 32,768）下，批内负样本数量充足且多样，无需额外挖掘难负样本。

### 零样本分类

在推理阶段，对 K 类的零样本分类流程为：

1. 对每个类别标签 c，构造文本提示：`"a photo of a {class}"`（提示工程很关键）。
2. 编码所有 K 个提示 → K 个文本嵌入。
3. 编码查询图像 → 1 个图像嵌入。
4. 预测与图像嵌入余弦相似度最高的类别。

无需微调，无需类别特定参数。模型能泛化是因为它在预训练中学到了图像与文本语义上相互映射的共享嵌入空间。

## 网络规模训练

CLIP 在 **WIT（WebImageText）** 上训练——4 亿对从互联网收集的图文对，未使用任何 ImageNet 标签。关键训练细节：

- 批量大小：最大 32,768——对于获得有效批内负样本至关重要。
- N² 负样本对通过分布式 all-gather 跨 GPU 计算，通信开销正比于批量大小。
- 混合精度（FP16）训练；虽然 [Hopper/H100 时代](../../foundational/hopper-h100/zh.md)工具链尚未出现，但相同原则适用。
- 最大模型（ViT-L/14@336px）总计算量约相当于 700 GPU 年。

使用嘈杂的网络数据而非精心标注标签，与 [Whisper](../whisper/zh.md) 处理语音识别的思路如出一辙。

## 核心公式

推理时使用的归一化余弦相似度：

$$\text{sim}(v, t) = \frac{v \cdot t}{\|v\| \cdot \|t\|}$$

其中 v 为图像嵌入，t 为文本嵌入，两者均已经过 L2 归一化（因此退化为点积运算）。

## 工程 Tradeoff

| 决策 | 得到什么 | 放弃什么 |
|---|---|---|
| 双编码器，无交叉注意力 | 编码后 O(1) 检索；图像与文本可独立编码并缓存 | 无法建模细粒度图文交互；精度要求高的任务需要交叉编码器重排 |
| 仅使用批内负样本 | 无需离线挖掘流程；随批量自然扩展 | 需要极大批量（32k+）才有足够覆盖率；通信开销随批量增长 |
| 可学习温度 τ | 训练中自适应调整分布锐利度 | 多一个需监控的超参数；τ 趋近于 0 时有发散风险 |
| 对称损失（双向） | 更丰富的梯度信号；嵌入对齐更好 | 相比单向约 2× 的损失计算量 |
| 网络爬取的嘈杂数据 | 接近零成本获得 4 亿图文对 | 嵌入空间中存在社会偏见和事实错误；需仔细评估偏差 |
| 共享嵌入空间 | 零样本迁移简洁；通用表示 | 文本与图像模态须对齐维度；将丰富视觉内容压缩为单一向量会丢失空间细节 |

## 实验与结果

- **零样本 ImageNet**：ViT-L/14 CLIP 在不使用任何 ImageNet 标签的情况下，以 76.2%（ViT-L/14@336px）的 top-1 准确率媲美有监督 ResNet-50。
- **迁移广度**：在 30 个多样化数据集（OCR、动作识别、地理定位、纹理）上评测，大多数任务上与有监督基线相当甚至更优。
- **线性探测**：冻结 CLIP 特征上的线性探测超过许多先前自监督方法的全量微调结果。
- **鲁棒性**：CLIP 嵌入对分布偏移的鲁棒性远优于标准 ImageNet 训练模型（ImageNet-A、ObjectNet 基准）。

## 个人评注

CLIP 的持久影响并不在于它的 ImageNet 数字——而在于这一认识：大规模训练的图文共享嵌入空间成为了跨模态的通用接口。每个后续 VLM（LLaVA、InstructBLIP、Flamingo、LLaMA-Vision）都将 CLIP 的 ViT-L/14 作为冻结的视觉骨干，用一个轻量投影器桥接到语言模型的嵌入空间。CLIP 本质上解决了"图像特征提取"问题，正如 BERT 解决了文本领域的同类问题——大规模训练一次，冻结，复用。

从基础设施角度看，CLIP 的双编码器结构具有显著的服务优势：图像嵌入可以离线预计算并缓存。对于面向固定图像语料库服务数百万查询的产品（如语义图像搜索），只需编码一次语料库，之后的查询只需一次矩阵乘法。同样的缓存逻辑也延伸到 VLM 服务中视觉 token 的[前缀缓存](../../foundational/prefix-caching/zh.md)。

主要局限性源于对比范式本身：CLIP 为每张图像生成单一向量，为每段文本生成单一向量——所有空间结构和组合结构都被压缩掉了。这正是 LLaVA 风格系统保留 ViT 编码器全部 patch token 序列而非池化 CLS token 的原因——空间 token 携带的信息对于基于定位的问答任务要丰富得多。CLIP 作为零样本分类器固然优雅，但作为特征骨干，当你保留每个 patch 的特征而非池化输出时，它才最为强大。
