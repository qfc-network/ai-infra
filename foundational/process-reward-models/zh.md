# 过程奖励模型（PRM）

- **作者 / 机构**：Lightman 等（OpenAI，PRM800K）；Luo 等（DeepSeek，MCTS+PRM）；Wang 等（加州大学伯克利分校，MC 回滚标注）
- **发表时间**：2023-05（Lightman arXiv:2305.20050）；2024-06（Wang arXiv:2406.06592）；2024-08（Snell arXiv:2408.03314）
- **链接**：[Lightman et al. PRM800K (arXiv:2305.20050)](https://arxiv.org/abs/2305.20050) · [Wang et al. MC 标注 (arXiv:2406.06592)](https://arxiv.org/abs/2406.06592) · [PRM800K 数据集](https://github.com/openai/prm800k)

## 一句话总结

**结果奖励模型（ORM）** 对完整推理链打分：正确或错误。**过程奖励模型（PRM）** 对每个推理*步骤*打分：给定前序步骤，这一步是否有效？这一区别至关重要，因为大多数推理错误是局部的——在第 4 步出错的推理链，前 3 步仍然正确；而最终答案正确的推理链，内部推理过程可能存在缺陷。在步骤级人工标注（PRM800K，80 万条步骤）上训练的 PRM，在所有采样数量下均显著优于 ORM。它是推理时扩展中 PRM 引导 best-of-N 和束搜索的验证器，也是 GRPO 组相对优势向逐步信用分配迈进的缺失组件。瓶颈在于：步骤级标注成本高昂。蒙特卡洛回滚标注（通过步骤导向正确答案的经验概率自动标注）使 PRM 无需人工标注即可训练，代价是标签噪声。

## 背景与动机

### 为何结果监督不够

标准 RLHF 在（问题、答案、正确/错误）对上训练 ORM。ORM 对完整轨迹赋予标量奖励。对于推理任务，这有两种失效模式：

1. **信用分配粒度过粗。** 错误答案可能仅由十步中的一步失误导致。ORM 对所有十步一视同仁惩罚——九个正确步骤与一个错误步骤获得相同的负梯度信号。

2. **通过正确答案技巧奖励黑客。** 策略可以学会产生看似合理的步骤，然后猜出正确答案，完全没有真正的推理。ORM 奖励正确的最终答案，不论推理过程如何。

PRM 同时解决这两个问题：步骤级分数实现精确信用分配；对每个步骤的局部有效性打分的 PRM 更难被攻击——即使最终猜对了答案，模型也无法通过十步错误推理获得高 PRM 分数。

### 推理时扩展的联系

如[推理时扩展条目](./inference-time-scaling/)所述，best-of-N 搜索和束搜索的有效性关键取决于验证器的质量：

- **ORM best-of-N**：生成 N 条推理链，返回 ORM 分最高的。当模型频繁产生正确最终答案时有效；当模型频繁产生"看起来正确"的错误答案时失效。
- **PRM best-of-N**：对每条链的每个步骤打分；选择 PRM 分最高的链（步骤分的乘积或最小值）。PRM 能捕捉 ORM 遗漏的错误，因为它评估推理过程，而非结论。
- **PRM 束搜索**：逐步生成推理；每步用 PRM 对部分链打分；保留 top-B 束并剪枝其余。将推理计算量集中在 PRM 分最高的推理路径上。

Lightman 等（PRM800K）证明，在所有测试采样数（N = 4 至 N = 1860）下，PRM 引导 best-of-N 比 ORM best-of-N 高 5–15% 绝对值。在 N=1860 配合 PRM 引导下，GPT-4 在 MATH 500 上从 78.2% 提升至 90.1%。

## 核心方法

### PRM 预测什么

PRM 是一个带标量头的语言模型，对推理链中的每个步骤 `s_i` 预测：

```
PRM(s_i | 问题 q, 步骤 s_1, ..., s_{i-1}) → p ∈ [0, 1]
```

其中 `p` 是在给定前序步骤的情况下步骤 `s_i` 正确的概率。模型看到直到 `s_i` 的完整链，在指定 token（通常是换行符或步骤分隔符）处输出分数。

链级 PRM 分数是步骤分的**乘积**（惩罚任何错误步骤）或**最小值**（识别最薄弱环节）。乘积对搜索时排序更具区分度；最小值更易解释。

### 人工标注：PRM800K

Lightman 等通过让承包商对 MATH 题目的 GPT-4 推理链中每个步骤进行评级，收集了 80 万条步骤级标注。每个步骤被标记为：

- **正向**：正确且有效
- **负向**：包含错误
- **中性**：无数学意义（格式调整、重述题目）

这需要约 3,000 小时的承包商时间，覆盖约 12,000 道 MATH 题目的 75,000 条唯一解题过程。关键发现：承包商间一致率约为 80%——某些步骤确实存在模糊性，尤其是步骤并非*错误*但采取了次优方式时。

PRM 随后被训练为在（链前缀、步骤、标签）三元组上的二元分类器，使用带价值头的语言模型骨干：

```
loss = -[y · log(PRM(s_i)) + (1-y) · log(1 - PRM(s_i))]
```

其中正向标签 `y = 1`，负向标签 `y = 0`。

### 蒙特卡洛回滚标注（自动标注）

人工标注成本高昂且特定于领域（PRM800K 仅覆盖 MATH）。Wang 等（2024）提出**蒙特卡洛回滚标注**：对训练链中的每个步骤 `s_i`，通过从 `s_i` 到链末尾采样 K 次完整推理并检验是否得到正确答案，来估计其正确性：

```
p̂(s_i 正确) = (从 s_i 出发得到正确答案的完整推理次数) / K
```

该自动标签随后用作 PRM 的训练目标。直觉如下：正确的推理步骤应该频繁导向正确的最终答案；错误步骤不太可能恢复。

MC 标注需要：
- 最终答案的验证器（MATH 的符号数学引擎，代码的单元测试）
- 每步 K 次回滚完整推理（通常 K = 4–16）
- 生成回滚的策略模型（可以是正在训练的模型本身）

**噪声特性**：MC 标注在两个方向上存在噪声：
- 正确步骤可能导向错误答案（若后续步骤失败）——低估步骤质量
- 错误步骤可能偶然导向正确答案——高估步骤质量

实践中，链早期步骤被低估（从正确前提出发失败概率小），链后期步骤被高估（接近答案，即使步骤不佳也无关紧要）。校准技术（logit 输出的温度、标签平滑）有所帮助。

### PRM 架构

PRM 与策略模型共享骨干（相同分词器、相同架构）。两种变体：

1. **独立 PRM**：从零或从 SFT checkpoint 独立训练，在（链、步骤分）标注数据上。训练隔离更清晰；可以比策略更小（为 70B 策略训练 3B–7B PRM 很常见）。

2. **策略上的价值头**：为策略添加线性标量头，联合训练。策略与 PRM 共享表示，参数效率更高；若 PRM 目标与语言建模目标冲突，可能产生干扰。

对于束搜索或 MCTS 下的服务，PRM 需要快速。为此优先选择独立的、更小的 PRM——PRM 推理在每个束步骤运行，延迟直接乘倍。

### 与搜索的整合

**带 PRM 的 Best-of-N：**
```
for 每条候选链 c in [c_1, ..., c_N]：
    score(c) = ∏_i PRM(s_i | q, s_{<i})   # 或取 min
return argmax_c score(c)
```

**束搜索：**
```
beams = [([], 1.0)]   # (部分链, 分数)
for step 1..T：
    candidates = []
    for (chain, score) in beams：
        for next_step in generate_candidates(chain, q, B)：
            new_score = score × PRM(next_step | q, chain)
            candidates.append((chain + [next_step], new_score))
    beams = top-B(candidates)   # 剪枝至束宽 B
return beams[0]
```

每步中，`generate_candidates` 从策略采样 B 个候选下一步；PRM 对每个打分；只有 top-B 存活。这将计算量集中在高 PRM 分的前缀上。代价：每步 B 次 PRM 推理调用，加上 B 次策略调用。

**带 PRM 的 MCTS：**
PRM 作为 MCTS 中的价值函数：节点（部分推理链）的价值由 PRM 分估计。这避免了为估计节点价值而进行完整回滚的需求——PRM 提供即时价值估计。DeepSeek-R1 报告讨论了 MCTS 作为生成高质量 SFT 数据的搜索策略；PRM 是使推理上的 MCTS 实用的关键组件。

## 工程权衡

| 决策 | 得到什么 | 放弃什么 |
|---|---|---|
| 人工标注（PRM800K 式） | 高质量、校准良好的标注；即使对模糊步骤也有良好信号 | 每个领域约 3k 小时；无法扩展到少数几个 benchmark 之外；标注者需要领域专业知识 |
| MC 回滚自动标注 | 可扩展到任何可验证领域；无需人工标注；随策略改进自我提升 | 标签噪声（链边界处的低估/高估）；数据生成时每步需要 K 次回滚；策略弱时早期训练噪声大 |
| 独立 PRM（更小） | 束/MCTS 推理速度快；与策略训练隔离 | 策略变化显著时需重新训练；需要管理两个模型 checkpoint |
| 策略上的价值头 | 参数效率高；共享表示 | 干扰风险；若平衡不当，PRM 头可能降低 LM 质量；推理时模型更大 |
| 步骤分的乘积 vs 最小值 | 乘积：对链排序更具区分度 | 任意步骤错误时乘积归零——梯度不稳定；最小值：更稳定但表达力较弱 |
| 束宽 B（1 → 16） | 更大的 B：发现更好的推理路径 | 更大的 B：每步 B 倍 PRM 推理；B 倍策略推理；B 个 KV cache 的内存 |

## 实验与结果

**PRM800K（Lightman 等，2023）：**
- ORM best-of-N（MATH，N=1860）：72.4%
- PRM best-of-N（MATH，N=1860）：78.2%
- 均以 GPT-4 为基础模型；在最大 N 下绝对增益 6%
- 在 N=8（实际计算预算）时：ORM 62%，PRM 68%——6% 的绝对增益在所有 N 值下保持稳定

**MC 回滚标注（Wang 等，2024）：**
- Math-Shepherd（他们的方法）：7B 模型 + MC 标注 PRM 在 MATH 上达 84.1%（vs ORM best-of-N 基线 78.6%）
- MC 标注比人工标注噪声更大，但无需标注成本即可推广到新领域
- 当每步 K=4 次回滚时，自动标注 PRM 在 MATH 上与人工标注 PRM 相差 3–4%

**推理时扩展（Snell 等，2024）：**
- MATH 500 上的 PRM 束搜索：在相同总 FLOP 预算下，比扁平 best-of-N 高 5–10% 绝对值
- 增益在困难问题（AMC、AIME 难度）上最大——正是模型最受益于步骤级引导的地方

## 可复现性说明

- **PRM800K 数据集**：已在 [github.com/openai/prm800k](https://github.com/openai/prm800k) 公开发布，覆盖 GPT-4 解题过程的 MATH 题目。在无新标注的情况下不易推广到其他领域。
- **Math-Shepherd 数据集**：Wang 等发布，用于 MC 标注数学 PRM。质量低于 PRM800K 但覆盖范围更广。
- **训练 PRM**：使用任何带标量头的 LM。HuggingFace `transformers` + 步骤分隔符 token 上的回归或二元 CE 头可行。难点在于一致地分词步骤边界——PRM 在训练和推理时必须看到相同的步骤分隔符。
- **为束搜索服务 PRM**：将 PRM 作为独立进程与策略分开运行；使用异步批处理，使 PRM 调用不阻塞策略生成。在 B=8 和 20 步时，每次查询需要发出 160 次 PRM 推理调用——同步时延迟严重堆积。
- **MC 回滚生成**：计算密集。为 1000 步训练集中每步生成 K=4 次回滚需要 4000 次完整推理。使用 vLLM 提升吞吐；将相同前缀的所有回滚批量处理，最大化 KV cache 复用。

## 评注

PRM 是 RLHF 留下的一个问题的答案：**模型在推理链的哪里出错了？** ORM 只能告诉你模型错了；PRM 能告诉你它在第 4 步出错了。这种步骤级信号改变了可能性：你可以在推理步骤上而非完整链上搜索，可以在错误位置精确提供梯度信号，还可以构建能解释解题*为何*错误（而非仅仅*是否*错误）的可解释系统。

MC 回滚方法尤其重要。它通过使用模型本身来估计步骤质量，打破了对昂贵人工标注的依赖——步骤好不好，就看它能否导向正确答案。这在哲学上与 GRPO 用规则奖励替代奖励模型类似：两种做法都减少了人工标注瓶颈。代价也相同：需要可验证的领域。对于数学和代码，最终答案验证成本低廉。对于开放式推理，不存在廉价的最终答案验证器，而在 MATH 上训练的 PRM 也不能推广到其他领域。

三个定义当前前沿的开放问题：

**1. PRM 泛化性。** PRM800K 覆盖 MATH；Math-Shepherd 覆盖小学数学。目前没有经过良好验证的用于代码（单元测试是过程验证器，但非步骤级）、科学推理或多跳事实问答的 PRM。每个构建推理模型的实验室都需要自己的特定领域 PRM 流程。

**2. PRM 古德哈特定律。** 针对 PRM 用 GRPO 或 RL 训练的模型学会产生 PRM 喜好的推理，而未必是正确的推理。PRM 对局部连贯但整体出错的步骤给出高分。这是过程级别的奖励黑客，在实验中可以观察到——针对 PRM 微调的模型有时会表现出 PRM 奖励的文体模式，而不提升实际正确率。定期用新策略样本重新训练 PRM 是标准缓解措施；成本高昂。

**3. 长推理链上的 PRM。** 在 4,000+ token 的推理轨迹（R1 级模型的典型情况）下，步骤级 PRM 必须对每条链进行数百次评分调用。乘积聚合使数值不稳定性加剧。替代聚合方式（步骤分上的学习池化、步骤分序列上的注意力）正在探索中，但尚未成为标准实践。

对从业者而言：如果你有可验证的任务并想提升推理质量，在投入 GRPO 之前先训练一个小型（7B–13B）MC 标注的 PRM。N=16 的 PRM 引导 best-of-N 通常比一轮 GRPO 更便宜、更有效，且不需要在线回滚基础设施。有了可用的 PRM 信号后，再在此基础上叠加 GRPO。
