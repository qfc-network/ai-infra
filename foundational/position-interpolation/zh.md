# 位置内插：YaRN、LongRoPE 与 NTK 感知缩放

- **作者 / 机构**：Chen 等（Meta）· Peng 等（Eleuther AI / 微软）· Ding 等（微软）· kaiokendev（NTK 感知，独立研究者）
- **发表时间**：PI: 2023-06（arXiv:2306.15595）· YaRN: 2023-09（arXiv:2309.00071）· LongRoPE: 2024-02（arXiv:2402.13753）· NTK 感知: 2023-07（博客文章）
- **链接**：[PI 论文](https://arxiv.org/abs/2306.15595) · [YaRN 论文](https://arxiv.org/abs/2309.00071) · [LongRoPE 论文](https://arxiv.org/abs/2402.13753)

## 一句话总结

RoPE（旋转位置编码）通过以训练时标定的频率旋转查询/键向量来编码位置信息。超出训练上下文长度后，这些频率产生模型从未见过的旋转角度，导致困惑度飙升、连贯性崩溃。位置内插（PI）通过线性缩放位置索引使其落在训练范围内来解决这一问题。NTK 感知缩放通过改变 RoPE 底频而非位置索引来改进 PI，让高频（局部）维度受到的扭曲更小——且关键在于无需任何微调即可零样本使用。YaRN 进一步以非均匀的逐频率缩放和注意力温度校正优化了这一方案，仅需数百步微调即可在 128k 上下文下实现近乎无损的困惑度。LongRoPE 通过对逐频率缩放因子进行进化搜索，将最高支持上下文推进至 200 万 token。

## 背景与动机

### RoPE 外推失效的根本原因

正如[RoPE 条目](../rope/zh.md)所述，RoPE 通过以 d/2 个频率旋转 d 维查询/键向量来编码位置 m：

```
θ_i = base^{-2i/d}，i = 0, 1, ..., d/2 - 1   （默认 base = 10,000）
```

在训练上下文长度 L_train 内，模型见过所有 m ∈ [0, L_train) 范围内的旋转角度 m · θ_i，这些值被训练分布充分覆盖。

当推理时 m > L_train：
- **高频维度**（θ_i 小，旋转快，在 L_train 内完成多圈完整旋转）：m · θ_i 只比训练范围略微超出——这些维度的外推相对合理。
- **低频维度**（θ_i 大，旋转慢，在 L_train 内不足一圈）：m = 2 × L_train 时，m · θ_i 是训练最大角度的 2 倍——这些维度严重超出分布。

结果：2 倍训练长度处的困惑度可上升 10–100 倍，生成连贯性完全崩溃。这不是理论问题——当开发者尝试服务超过训练长度的上下文时，这一现象被反复实验证实。

### 为什么不直接用更长上下文训练？

从头在 128k 上下文下训练需要：
1. **KV 缓存内存**：128k token 时，32 层 70 亿参数模型的单序列 KV 缓存约 32 GB——在训练批量大小下不可行。
2. **注意力计算量**：注意力复杂度与序列长度的平方成正比；128k 上下文的每 token 计算量是 4k 的 32 倍。
3. **长上下文数据稀缺**：12.8 万 token 以上的文档极少；无论如何，训练分布由短序列主导。

实际方案：在可管理的上下文长度（4k–8k）下训练，然后通过只需少量微调步骤（甚至无需微调）的后训练技术扩展上下文。

## 线性位置内插（Chen 等，2023）

### 核心思路

对于长度 m > L_train 的序列，不使用位置索引 0, 1, ..., m-1，而是将其缩小：

```
m → m · (L_train / L_target)
```

这将位置 [0, L_target) 线性映射到 [0, L_train)，确保推理时所有旋转角度都在训练分布范围内。当 L_target = 2 × L_train 时，每个位置索引减半。

**代价**：可区分的最小位置差加倍。L_train = 4096、L_target = 8192 时，原本相距 1 步的位置，在模型看来变成相距 0.5 步——低于模型在训练中学会区分的精度。这就是"位置混淆"或"内插模糊"问题。

**微调要求**：仅做位置内插（不微调）时，困惑度比朴素外推有所改善，但仍有退化。Chen 等发现，在长上下文文档上进行 1000 步微调足以让模型适应新的更细粒度。微调后，模型能学会在新的更小间隔下区分位置。

**结果**：LLaMA 7B 通过 1000 步微调从 2k 扩展至 32k 上下文。32k 处密钥检索准确率：约 100%。长文档基准：与原生在更长上下文训练的模型相当。

## NTK 感知内插（kaiokendev，2023）

### 神经切核的洞见

来自神经切核（NTK）理论的关键观察：压缩信号（通过缩放位置索引）时，会丧失高频分量的表示能力。对所有频率均匀内插类似于低通滤波——它破坏了高频维度编码的精细局部位置信息。

解决方案：不缩放位置，而是改变 RoPE 的**底频**，使每个维度的波长按比例拉伸：

**核心公式——NTK 感知底数变换：**

```
θ'_i = (base · s^(d/(d-2)))^{-2i/d}
```

等价地：

```
新底数 = base · s^(d/(d-2)}，其中 s = L_target / L_train
```

举例：base = 10,000，L_train = 4096，L_target = 32768（s = 8），d = 128：

```
新底数 = 10,000 · 8^{128/126} ≈ 10,000 · 8.13 ≈ 81,300
```

**为什么有效**：改变底数拉伸了每个频率维度的波长，使每个维度在目标上下文长度处的旋转角度保持在合理范围内。最关键的是，高频维度（编码局部、精细位置信息）受到的压缩**比线性内插更小**，因为它们本来波长就短，能以更小的相对失真吸收拉伸。

**零样本能力**：NTK 感知缩放在推理时无需任何微调即可使用。只需在模型配置中修改 `rope_theta` 参数。这正是它在生产推理服务器中被广泛采用的原因——无需微调即可扩展现有模型的上下文。

**局限**：在极长上下文（>4 倍训练长度）且无微调的情况下，NTK 感知缩放会出现质量退化，尤其是需要精确长程注意力模式的任务。在生产长上下文场景中仍建议微调。

## YaRN：非均匀频率缩放（Peng 等，2023）

### 动机

线性 PI 和 NTK 感知缩放都只应用单一缩放因子——分别作用于位置（PI）或底数（NTK）。但不同频率维度本质上具有不同属性：

- **高频维度**（旋转快，波长短）：编码短程内的局部 token 顺序和相对位置。这些维度不应被内插——它们在自身范围内是正确的。
- **低频维度**（旋转慢，波长长）：编码文档内的全局位置。这些维度超出 L_train 后会严重偏离分布，需要内插。
- **中频维度**：介于两者之间。

YaRN 应用频率相关的缩放：

```
对于维度 i：
  若 λ_i < √L_train / (2π)：      # 高频：不内插
      γ = 1.0
  若 λ_i > √L_target / (2π)：     # 低频：完全内插
      γ = s = L_target / L_train
  否则：                            # 线性过渡
      γ = 1 - (β - λ_i) / (β - α)  # α、β 为频率边界
```

其中 λ_i = 2π / θ_i 为维度 i 的波长。

**注意力温度校正**：位置索引缩放后，内积 q^T R_{n-m} k 的幅值发生变化。YaRN 对注意力 logit 施加温度因子 `1/√t`：

```
注意力分数 → 注意力分数 / √t
```

其中 t 经验性地设为约 0.1 × log(s) + 1。这将注意力分布校正为与训练上下文长度相同的有效"注意力温度"。

### 实际性能

YaRN 使用 4k 上下文训练的 LLaMA 2 7B 和 13B 模型，仅需 400 步微调即可在 32k–128k 上下文下实现近乎无损的困惑度。这比线性 PI 所需的步数少得多。注意力温度校正至关重要——没有它，长上下文困惑度明显更差。

YaRN 现已成为最主流的上下文扩展实用方法，在 HuggingFace Transformers 中通过 `rope_scaling = {"type": "yarn", ...}` 配置即可使用。

## LongRoPE（Ding 等，2024）

LongRoPE 通过**进化搜索**对逐频率缩放因子进行优化，直接以保留集上的长上下文困惑度为目标，扩展了 YaRN 的非均匀缩放思路。与 YaRN 的解析斜坡函数不同，它对 d/2 个频率维度中每一个独立搜索最优缩放因子。

**两阶段方案**：
1. 在目标上下文长度（如 51.2 万）上搜索最优逐频率缩放因子。
2. 用这些因子进行少量步骤的微调；然后通过第二阶段搜索进一步将上下文扩展至 200 万。

**结果**：在 Phi-2 和 LLaMA 模型上实现 200 万上下文长度，困惑度与原生训练在该长度的模型相差不超过 0.5 bits/token。进化搜索约耗时 1 个 GPU 天。

**应用于**：Phi-3-mini、Phi-3-small（微软，2024）。

## 内存与算力影响

上下文扩展方法本身对前向传播几乎不增加开销——它们只是改变位置索引或底频的计算方式。长上下文服务的主要开销在于 KV 缓存：

```
每序列 KV 缓存 = 2 × L × 层数 × KV 头数 × 头维度 × 每元素字节数
```

以 70 亿参数模型（32 层、32 个 KV 头、头维度 128、bf16）在 128k 上下文下计算：

```
= 2 × 131,072 × 32 × 32 × 128 × 2 = 68 GB
```

这是单个序列在 128k 时消耗的 GPU 内存。这正是为什么环形注意力（见[ring-attention 条目](../ring-attention/zh.md)）和分块预填充（见[chunked-prefill 条目](../chunked-prefill/zh.md)）是生产系统中位置内插的必要配套——你需要将 KV 缓存分布到多个设备上。

与此同时，128k 上下文下的预填充计算量也是 4k 的 1024 倍（二次方缩放）。70 亿参数模型预填充 12.8 万个 token 在单张 A100 上需要约 10–15 秒。

## 工程权衡

| 决策 | 收益 | 代价 |
|---|---|---|
| 线性 PI（Chen 等） | 简单；零新增参数；少量微调即可使用 | 对所有频率均匀压缩；高频维度丧失局部位置分辨率 |
| NTK 感知（零样本） | 无需微调；开箱即用；可立即用于生产部署 | >4 倍训练长度时质量退化；不微调不适合精确长上下文任务 |
| NTK 感知 + 微调 | 质量优于同等微调预算下的 PI | 需要选择新底数；比 PI 略复杂 |
| YaRN | 32k–128k 近乎无损质量；所需微调步骤远少于 PI | 超参数更多（α、β 频率边界，温度 t）；解析斜坡是近似 |
| LongRoPE（进化搜索） | 51.2 万–200 万上下文下已知最佳质量；逐维度最优 | 搜索成本约 1 GPU 天；难以复现；适配新模型较复杂 |
| 预训练时使用大 θ 底数（Llama 3：50 万） | 无需后训练扩展的原生长上下文能力 | 需要完整重训；短上下文位置区分度略有下降 |

## 实验结果

**线性 PI（Chen 等，2023）**：LLaMA 7B–65B 通过 1000 步微调扩展至 32k 上下文。32k 处密钥检索准确率：约 100%。SCROLLS 基准（长文档摘要、问答）：与原生长上下文训练模型相当。>16k 时，对需要精确局部排序的任务，位置分辨率退化可见。

**NTK 感知（kaiokendev，2023）**：在最长 8k（LLaMA 2 的 4k 训练长度的 2 倍）序列上，零样本困惑度与训练长度困惑度相差不超过 0.3 bits/token。无需微调。16k（4 倍）时，不微调的退化可见（约 1 bit/token）。

**YaRN（Peng 等，2023）**：4k 上下文训练的 LLaMA 2 7B 扩展至 128k。400 步微调后，128k 处困惑度与原生 128k 训练模型相差不超过 0.1 bits/token。128k 处密钥检索准确率：99.8%。400 步的 YaRN 在 64k 上优于 1000 步的 PI 在 32k 上（SCROLLS）。温度校正单独带来约 0.3 bits/token 的改善。

**LongRoPE（Ding 等，2024）**：Phi-2（27 亿参数）扩展至 200 万上下文。51.2 万上下文处困惑度与神谕值相差不超过 0.5 bits/token。128k 处 RULER 基准（长上下文检索任务）：比 YaRN 高出 3–4 分。

## 综合评述

位置内插体现了大模型基础设施中一个常见规律：一个理论上很小的变化（位置索引的计算方式）会产生出人意料的巨大二阶影响（模型能否服务长上下文）。从 PI → NTK 感知 → YaRN → LongRoPE 的演进路径，是一个严谨工程优化的典范：每次迭代都找出前一方法的瓶颈并针对性解决。PI 对所有频率均匀压缩；NTK 感知认识到频率重要性的非均匀性；YaRN 对其正式化；LongRoPE 给出最优解。

2024–2025 年生产系统的实际建议是：用大 θ 底数（50 万至 100 万）训练，并在需要进一步扩展时使用 YaRN。NTK 感知零样本技巧适合快速实验或无法进行微调的场景。LongRoPE 仅在需要超过 25.6 万 token 上下文的应用中才值得承担搜索成本。

开放问题是：这些方法究竟是提供了真正的长上下文能力，还是只是减少了困惑度退化？来自"迷失在中间"（Liu 等，2023）的研究表明，即便长上下文困惑度较低的模型，也可能无法关注到长文档中间位置的信息。位置内插解决了频率分布问题，但没有解决注意力模式问题（模型无论内容如何，都倾向于关注文档开头和结尾）。StreamingLLM（见[streaming-llm 条目](../streaming-llm/zh.md)）从完全不同的角度处理这一问题——限制上下文而非扩展上下文。
