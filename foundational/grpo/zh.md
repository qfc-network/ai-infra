# GRPO —— 组相对策略优化

- **作者 / 机构**：Shao 等，DeepSeek-AI
- **发表时间**：2024-02（arXiv:2402.03300）；DeepSeek-R1（2025-01）的核心算法
- **链接**：[DeepSeekMath 论文](https://arxiv.org/abs/2402.03300) · [DeepSeek-R1 技术报告](https://arxiv.org/abs/2501.12948) · [代码（DeepSeek-R1）](https://github.com/deepseek-ai/DeepSeek-R1)

## 一句话总结

用 PPO 做基于人类反馈的强化学习（RLHF），需要四个同时驻留的模型：策略、参考策略、Critic（价值网络）和奖励模型——总内存是单次推理的四倍，还要维护复杂且脆弱的 rollout 基础设施。GRPO（组相对策略优化）彻底去掉了 Critic。它不学价值函数来估计期望未来奖励，而是为每个 prompt **采样一组响应**，对全组打分，用**组内每条响应奖励的相对排名**作为优势估计。无 Critic 训练，无 Critic 内存，无价值函数引导。结合规则型奖励去掉奖励模型（如 DeepSeek-R1-Zero），GRPO 把训练时的模型数量压缩到两个（策略 + 参考），同时在数学推理上达到当时最优水平。GRPO 是 DeepSeekMath、DeepSeek-R1 以及 2025 年开源推理模型浪潮背后的训练算法。

## 背景与动机

### PPO 的内存与基础设施负担

PPO（近端策略优化，Schulman 等 2017）是大模型后训练中主导的 RL 算法。标准的 PPO-RLHF 配置需要：

1. **策略模型（π_θ）**：被训练的模型，每次梯度步更新。
2. **参考策略（π_ref）**：初始 SFT 模型的冻结副本，用于计算 KL 散度惩罚，防止策略偏离 SFT 基线过远。
3. **奖励模型（RM）**：在人工偏好数据上单独训练，用于在 rollout 期间给完成结果打分。
4. **Critic / 价值网络（V_φ）**：另一个神经网络（通常与策略同规模，加一个 value head），估计 V(s)——从状态 s 出发的期望累积奖励。计算 PPO 优势 A(s,a) = Q(s,a) − V(s) 必须用到它。

对 7B 策略来说，这意味着 4 个模型 × 约 14 GB = 至少 56 GB，激活和优化器状态还没算。70B 规模下内存需求骇人。除内存外，rollout 阶段——从策略采样、用 RM 打分、跑 Critic 前向、计算优势、再跑策略反向——每个训练步有五个独立的神经网络操作，时序上需要精确协调以避免值过期。

Critic 尤其棘手。在快速变化的策略旁边训练一个价值网络本身就极不稳定（"移动目标"问题）。价值函数估计误差会叠加进噪声优势估计，进而破坏策略梯度。PPO 出了名的脆弱，很大程度上源于 Critic 的不稳定。

### 洞察：无 Critic 的组相对优势

GRPO 的问题是：我们真的需要学习一个价值函数来估计优势吗？优势函数存在的目的是降低策略梯度估计的方差——它告诉策略"这个动作比平均水平好（或差）多少"。

更简单的替代方案：不学 V(s) 来估计基线，直接**为同一个 prompt 采样多条响应**，用这组响应的奖励分布作为自然基线。第 i 条响应的优势就是它的奖励比组内平均高出多少。不需要 Critic。

这个思路在 contextual bandit 和带基线的 REINFORCE 中都有先例，但把它干净地应用到带 PPO 式裁剪和 KL 正则化的大模型后训练中，是 GRPO 的贡献。

## 核心方法

### 算法流程

每个训练步：

1. **为批中每个 prompt q 从当前策略采样 G 条响应**：
   ```
   {o₁, o₂, ..., o_G} ~ π_θ_old(· | q)
   ```

2. **用奖励信号对每条响应打分**：得到 {r₁, r₂, ..., r_G}。

3. **计算组相对优势**：
   ```
   Â_i = (r_i − mean({r₁,...,r_G})) / std({r₁,...,r_G})
   ```
   这是组内的简单 z-score 标准化。优势对组内高于均值的响应为正，低于均值的为负。

4. **用 PPO-clip 式目标加 KL 正则化更新策略**：

```
L_GRPO(θ) = E_{q, {o_i}} [
    (1/G) Σ_i  min(ρ_i · Â_i,  clip(ρ_i, 1-ε, 1+ε) · Â_i)
] − β · KL(π_θ || π_ref)
```

其中 ρ_i = π_θ(o_i | q) / π_θ_old(o_i | q) 是重要性比率（当前策略 vs 生成样本时的策略的概率比），ε 是裁剪系数（通常 0.2），β 是 KL 惩罚系数。

KL 项让策略靠近参考（冻结的 SFT 模型），在防止奖励黑客的同时允许有意义的更新。实践中 KL 可以逐 token 用参考模型的 log 概率来估计——这要求参考模型每训练步做一次前向传播（不可避免，这就是即使去掉 Critic 和 RM，仍然需要两个模型的原因）。

### 为什么有效：组归一化的方差削减

标准 REINFORCE 梯度估计方差高，因为原始奖励信号有噪声且未去中心。带 Critic 的 PPO 通过减去价值基线 V(s) 来降低方差，但 Critic 本身引入了偏差和不稳定性。

GRPO 的组相对基线在不需要学习价值函数的情况下实现方差削减：
- 在组内归一化后，优势估计天然均值为零、方差为一。
- 组起到了 prompt 条件下奖励基线的局部在线估计作用——类似学习到的 Critic，但没有梯度不稳定问题。
- 更大的组规模 G 降低估计方差（更多样本 → 更稳定的均值/标准差），代价是更多 rollout 计算。

### 规则型奖励：去掉奖励模型

在 DeepSeek-R1-Zero 中，GRPO 结合的是**可验证的规则型奖励**，而不是学习到的奖励模型：

- **正确性奖励**：最终答案正确（通过符号比较或代码执行验证）得 1，否则得 0。
- **格式奖励**：遵循预期输出格式（如把推理包在 `<think>` 标签里、答案在 `<answer>` 标签里）有小加分。

规则型奖励是二值确定的——无歧义、无分布偏移、无需 RM 训练。这把第四个模型彻底去掉，训练时只需策略 + 参考。代价：规则型奖励只适用于可验证领域（数学、代码、逻辑谜题）。开放任务（写作、摘要、通用 helpfulness）仍然需要学习到的 RM 或人工反馈。

## 工程 Tradeoff

| 决策 | 得到什么 | 放弃什么 |
|---|---|---|
| GRPO vs PPO（去掉 Critic） | 内存中只需 2 个模型而非 4 个；消除 Critic 不稳定性；训练循环更简单 | Critic 能提供更细粒度的逐 token、逐状态价值估计；GRPO 优势只在响应级别（无子响应功劳分配） |
| 组规模 G（4 → 64） | 更大 G：优势估计方差更低；策略得到更清晰信号 | 更大 G：每个 prompt G 倍的 rollout 计算；同时在内存中存 G 条完成结果 |
| 规则型 vs 学习奖励 | 稳定、校准好、无需 RM 训练；无 RM 分布偏移导致的奖励黑客 | 对可验证领域的硬约束；无法奖励细腻的质量、语气或开放式创意 |
| KL 惩罚 β（0 → 0.1） | 防止奖励黑客；锚定在 SFT 行为上；训练稳定 | 限制策略能偏离参考的幅度；可能压制策略应当探索的新策略 |
| GRPO vs DPO | 在线 RL：可用不可微奖励、规则信号、实时探索 | DPO 更简单（离线，无 rollout）；GRPO 需要 rollout 基础设施，计算量更大 |

## 实验与结果

**DeepSeekMath（Shao 等，2024）：**
- 基础：在 1,200 亿数学 token 上微调的 DeepSeek-Coder-v1.5-7B。
- 在 SFT checkpoint 上跑 GRPO，用在数学题/解答对上训练的奖励模型。
- 结果：MATH benchmark 51.7%（vs 仅 SFT 基线的 34.9%），GSM8K 88.2%。超过同体量所有模型，包括部分闭源模型。
- GRPO 相比仅 SFT 在 MATH 上绝对提升约 15%，而 PPO 提升约 12%——但 GRPO 内存占用只有一半，代码更简单。

**DeepSeek-R1-Zero（DeepSeek-AI，2025）：**
- 策略：DeepSeek-V3-Base（671B MoE）。训练：GRPO + 规则型正确性 + 格式奖励，无 RM、无 SFT 预热。
- 涌现行为：模型自发地发展出扩展的思维链推理、自我验证和回溯策略——纯粹来自带二值奖励的 RL，没有用任何人工标注的思维链数据。
- AIME 2024：pass@1 71.0%（OpenAI o1 为 79.2%）。MATH-500：97.3%。
- R1-Zero 证明了 GRPO + 规则型奖励可以在完全没有标注推理数据的情况下教会大模型推理——这是一种质性不同的训练范式。

**DeepSeek-R1（DeepSeek-AI，2025）：**
- 在 R1-Zero 的 GRPO 骨干上加入冷启动 SFT 数据和迭代 RL 轮次。AIME 2024：79.8%（匹配 OpenAI o1）。从 R1 蒸馏出的变体（1.5B–70B）成绩强劲，证明推理能力通过蒸馏可转移。

## 复现要点

DeepSeek-R1 的原始 GRPO 训练代码已在 https://github.com/deepseek-ai/DeepSeek-R1 开源。社区也产出了若干高质量开源复现：

- **TRL（HuggingFace）**：v0.13（2025）新增 `GRPOTrainer`，适用于 HuggingFace hub 上的任意模型，奖励可以是可调用的函数（支持规则型奖励）。`pip install trl`，使用 `GRPOConfig`。
- **OpenRLHF**：功能完整的 RLHF 框架，支持 GRPO，为多节点训练设计，处理基于 vLLM 的大模型 rollout 生成。
- **veRL（火山引擎 RL）**：字节跳动的 RL 框架，也支持 GRPO，针对大规模分布式训练优化。

关键实现细节：
- **Rollout 生成是瓶颈**：G=8、batch size=64 时，每步生成 512 条完成结果。使用 vLLM 或 TGI 做快速 rollout；不要用 HuggingFace `generate()` 的默认方式。
- **组规模 G**：G=4 是最小值；G=8 在方差和计算量间取得好的平衡；奖励信号噪声很大时（如过程奖励模型）用 G=16–64。
- **KL 估计**：参考模型需要对每条 rollout 的每个 token 打分。这是完全可并行的，但内存加倍——参考模型放在单独 GPU 上，或用 CPU offload。
- **奖励归一化**：在组内归一化（如上描述），并在每批跨步做归一化，防止训练过程中量级漂移。

## 个人评注

GRPO 是近期 RL 领域一个原则的最清晰体现：**Critic 是降低方差的手段，不是目的本身**。Critic 存在是为了降低策略梯度估计的方差。如果你有更好、更廉价的降低方差的方式——比如为同一个 prompt 采样多条响应——就应该用那个。

规则型奖励的洞察（R1-Zero）可能比算法简化更重要。传统 RLHF 的故事是：你需要人工偏好数据、需要奖励模型、需要管理 RM 分布偏移和奖励黑客。R1-Zero 表明，对于可验证领域，这些都不需要——二值正确性就是足够的训练信号，可以产生世界级的推理能力。这把 RLHF 重新定位为设计空间中的一个点，而不是不可或缺的组件。

实际后果：GRPO + 规则型奖励现已成为推理模型训练的标准配方。论文发布后数周内，开源社区在 7B 和 32B 规模上复现了 DeepSeek-R1 的结果（Qwen-2.5-Math-GRPO、Sky-T1、STILL-3 等），证明这个技术是稳健且可及的。

尚待解决的问题：

- **功劳分配**：GRPO 的优势是响应级别的——对整个完成结果均匀奖励或惩罚。对于长链式思维响应，错误可能在 20 步中的第 5 步，但所有 token 收到相同的梯度信号。逐步功劳分配的过程奖励模型（PRM）存在，但训练昂贵，且尚未与 GRPO 干净地集成。
- **不可验证任务**：对于开放式生成（创意写作、细腻的指令跟随），规则型奖励不存在。GRPO 在这里仍然需要学习到的 RM，重新引入了它本来去掉的某个模型。
- **大 G 下的探索-利用**：非常大的组规模提高了方差削减，但也会把策略推向组的平均而不是最佳响应。最优 G 取决于奖励信号的噪声水平和模型的当前能力——不是普适常数。

对构建推理系统的实践者：如果任务可验证，从 GRPO + 规则型奖励开始。如果需要开放式质量，加一个轻量级 RM（3B–7B 规模，远小于策略），保持 GRPO 作为优化器。PPO 只在你已经摊销掉基础设施投入时才合理。
