# 推理时扩展 — 测试时计算量

- **作者 / 机构**：Snell 等（加州大学伯克利分校 / Google DeepMind）；并行工作：Brown 等（Scale AI）；基础采样工作：Wang 等（Google Brain）

## 核心摘要

训练计算量——部署前消耗的总 FLOP 数——五年来一直是 LLM 能力提升的主轴。推理时扩展（又称测试时计算量扩展）引入了第二个轴：**每次查询在推理时消耗的计算量**。在固定训练预算下，可以用推理 FLOP 换取更高的单次查询精度。核心机制有两种：**并行搜索**（生成多个候选答案，通过验证器选优）和**顺序细化**（思维链、扩展思考、迭代修正）。Snell 等（2024）证明这两种策略具有互补优势：并行搜索在"对模型困难但可验证"的问题上领先；顺序细化在需要模型无法在单次前向传播中压缩的多步推理问题上领先。推理时扩展最直观的体现是 o1/R1 系列推理模型——其"思考 token"本质上是通过 GRPO 训练出的自适应顺序细化。

## 背景与动机

### Chinchilla 墙之后

Chinchilla（Hoffmann 等，2022）确立了训练 FLOP 应在模型参数量和训练 token 数之间大致均分的原则。超越 Chinchilla 最优点需要按比例增加数据，而互联网规模的文本数据日益稀缺。社区一直在寻找第三个杠杆。

推理时计算量就是这个杠杆。直觉如下：一个 7B 模型生成 64 个候选答案，通过过程奖励模型选出最优答案，可能解决 70B 模型单次前向传播无法解决的问题。7B 模型训练成本更低、单 token 成本更低——代价转移到推理时，而推理时的成本可以用不同方式摊销（仅在困难查询上使用、在对延迟不敏感的场景中使用等）。

### 为什么这不只是"多采样"

朴素的 Best-of-N 采样（生成 N 个答案取多数投票）从自洽性研究（Wang 等，2023）开始就被证明能提升推理基准的准确率。但存在以下问题：

1. Best-of-N 扩展效率差：准确率随 N 的增长通常仅为 `log(N)` 或 `N^α`，对于困难问题需要极大的 N。
2. 需要可靠的方法从 N 个候选中挑出正确答案。多数投票在正确答案是最常见答案时有效；当模型几乎从不给出正确答案时，它就失效了。
3. 对于困难的多步问题，模型的失败模式往往是结构性的——无论采样温度如何，它在同一步骤上始终犯同样的错误，更多样本无济于事。

关键进展在于将采样与**过程奖励模型（PRM）**结合——PRM 对每个推理*步骤*评分，而非仅对最终答案评分——并从扁平并行搜索升级为 PRM 引导的**结构化搜索**（束搜索、MCTS）。

## 核心方法

### 策略一 — 带验证器的并行搜索

生成多条完整或部分推理链，用验证器选出最优：

**Best-of-N（结果监督）：** 独立采样 N 个答案，用结果奖励模型（ORM）对每个答案打分，返回得分最高的答案。当模型偶尔能解对问题时有效。Brown 等（2024）证明，7B 模型加 N=10,000 在 MATH 上能媲美甚至超越 70B 模型加 N=1——"键盘前的大语言猴子"。

**带 PRM 的 Best-of-N：** 不对完整答案打分，而用 PRM 对中间推理步骤打分。Lightman 等（PRM800K）在 80 万条人工标注推理步骤上训练了步骤级验证器；PRM 能捕捉 ORM 遗漏的推理链中段错误。在相同 N 下，PRM 引导的 Best-of-N 始终优于 ORM Best-of-N。

**推理步骤上的束搜索：** 逐步延伸推理链。每步维护 B 条部分推理链，用 PRM 对每个下一步打分，剪枝保留前 B 条。这将计算量集中在最有前途的推理路径上，而非均匀探索。Snell 等证明，在相同的推理 FLOP 预算下，PRM 束搜索在困难 MATH 子集上比扁平 Best-of-N 好 5-10%。

PRM 引导搜索的关键公式：给定由 K 个步骤组成的推理链 `s₁, s₂, ..., s_K`，PRM 赋予分数：

```
PRM(s₁..K) = ∏ᵢ p_PRM(sᵢ 正确 | s₁..ᵢ₋₁)
```

这种乘法结构意味着早期错误会使分数崩溃，即使后续步骤在局部上是连贯的——正确模拟了推理链中错误的传播。

### 策略二 — 顺序细化（思考 token）

不搜索并行候选，而是为单条推理链分配更多 token，让模型在给出答案前先推理。这就是"扩展思维链"或"思考"范式。

模型通过 GRPO 或类似 RL 学习在答案前输出 `<think>...</think>` 块。该块的内容不受监督约束——模型发展出自己的草稿本记法。涌现出的内容混合了：

- **有意的多步分解**：将困难问题拆解为可解的子问题
- **自我验证**：模型检查自己的中间步骤（一个弱内部 PRM）
- **回溯**：模型检测到错误路径后从较早的状态重新开始

计算成本与思考 token 长度成正比。对于需要 T 个思考 token 的问题，推理成本约为 `(T + A)` 个 token 等效的前向传播，其中 A 是答案长度——而非思考模型仅需 A 个 token。加速假设：花 T 个 token 思考的模型能解决它在 A 个 token 内永远无法解决的问题。

### 哪种策略用在何处？

Snell 等的核心实证发现，形式化为"计算最优"推理策略：

| 问题难度（相对于模型能力） | 最优策略 |
|---|---|
| 简单——模型几乎总是正确 | 无需额外计算；Best-of-1 足够 |
| 中等——模型正确率约 10–40% | 带 PRM 的并行搜索；正确性可验证且密度足够 |
| 困难——即使大量采样正确率 <5% | 顺序细化；并行搜索无法找到几乎不存在的针 |
| 超出模型能力 | 两者都无济于事；需要更强的模型或训练 |

核心洞察：当模型有合理概率生成正确推理链时，并行搜索才有效——你是在放大已有的信号。当模型需要构建单次前向传播无法产生的、本质上更长的推理路径时，顺序细化才有效——你是在启用一种质上不同的计算。

## 工程权衡

| 决策 | 收益 | 代价 |
|---|---|---|
| Best-of-N（并行） | 可并行化；无需架构改动；测试时无需训练 | N 倍 KV 缓存内存；N 倍吞吐成本；需要可靠验证器；随 log(N) 扩展 |
| 束搜索 + PRM | 相同 FLOP 预算下优于扁平 Best-of-N；能找到模型极少产生的正确推理链 | 每步 PRM 推理；束管理复杂度；PRM 质量成为瓶颈 |
| 思考 token（顺序） | 可解质上更难的问题；涌现自我验证；自适应——困难查询消耗更多 | 每查询不可并行；更高延迟；输出长度难以限定；需要 GRPO/RL 训练 |
| 自适应计算（按难度调整 N 或思考长度） | 高效：简单查询廉价，困难查询昂贵 | 需要查询时难度估计（本身是非平凡的分类器） |
| PRM vs ORM 作为验证器 | PRM 捕捉步骤级错误；精度更高 | PRM 训练需要步骤级标注（昂贵）；PRM 可能被模型"欺骗"——产生 PRM 喜好但实际错误的推理 |

## 实验与结果

**自洽性（Wang 等，2023）：**
- 在 GSM8K 上对 40 个样本多数投票：74.4% → 83.0%（PaLM 540B）。使用 40 个样本的 3-shot CoT 模型媲美大得多的模型在 1 个样本下的效果。
- 首次证明"多采样"是推理可靠的扩展轴。

**大语言猴子（Brown 等，2024）：**
- Llama-3 8B 在 MATH 上：pass@1 = 4%；pass@10,000 ≈ 78%。一个小模型加足够多样本和验证器，可以达到接近最优水平。
- 揭示了"模型能否产生答案"与"单次就能可靠产生"之间的巨大差距——这是两个截然不同的问题。

**PRM800K（Lightman 等，2023）：**
- GPT-4 使用 PRM 引导 Best-of-N 在 MATH 上：78.2% → 90.1%，优于相同 N 下的 ORM。
- 在所有测试 N 值下，过程监督（步骤级反馈）始终优于结果监督（最终答案反馈）。

**Snell 等"最优扩展测试时计算量"（2024）：**
- 在 MATH 500 道题上，最优分配推理计算量的 70B 模型准确率媲美 GPT-4。
- 在相同推理 FLOP 预算下，带 PRM 的束搜索在困难子集上比扁平 Best-of-N 高 5–10% 绝对值。
- 最优推理策略随问题难度分位数变化——验证了上述三阶段框架。

**DeepSeek-R1（2025）：**
- 671B MoE，通过 GRPO 训练思考 token。AIME 2024：79.8%（媲美 o1）。困难竞赛数学题的思考推理链平均长 4,000–8,000 token——是答案长度的 10–20 倍。

## 可复现性说明

**并行搜索：**
- 使用任何推理框架都可直接实现。`vllm generate(n=N)` 在单次批量前向中运行 N 个样本，无需修改代码。
- ORM：在（问题、答案、正确/错误）对上训练的标准 LM，用分隔符 token 的隐藏状态作为奖励头。
- PRM：更复杂。Lightman 等的 PRM800K 数据集已公开，仅覆盖 MATH。对于其他领域，通过蒙特卡洛回滚自动生成步骤级标注（测试某步骤是否在 k 次回滚中导致正确答案）是实用替代方案。

**顺序细化（思考模型）：**
- GRPO 训练方案详见 GRPO 条目和 DeepSeek-R1 技术报告。
- 开源复现：`trl.GRPOTrainer`（HuggingFace）、OpenRLHF、veRL。
- 关键基础设施挑战：训练期间的回滚生成会产生长度可变且往往极长的思考链。训练早期使用 `max_new_tokens` 上限防止推理链长度失控。
- 推理：思考模型需要足够大的 `max_tokens` 服务配置。vLLM 和 SGLang 支持动态序列长度；TensorRT-LLM 需要设置静态最大值。

**关键公开资源：**
- PRM800K 数据集：[github.com/openai/prm800k](https://github.com/openai/prm800k)
- DeepSeek-R1 权重和训练代码：[github.com/deepseek-ai/DeepSeek-R1](https://github.com/deepseek-ai/DeepSeek-R1)

## 评注

推理时扩展是 LLM 能力提升自预训练扩展律以来第一次结构性转变。五年来，"如何让模型更聪明？"的答案只有一个：用更多数据训练更长时间。现在有了两个答案：训练更多，或思考更多。

实际影响重大。7B 规模的思考模型能解决 70B 非思考模型无法解决的问题。每次查询的推理成本更高，但训练成本低一个数量级。对于许多用例——代码生成、数学、研究综合等对延迟不敏感的任务——这是正确的权衡。

三个尚未完全解决的张力：

**1. 验证器瓶颈。** 并行搜索的能力上限受验证器决定。对于数学和代码，存在真值验证器（符号求值、单元测试）。对于开放式任务——摘要、分析、创意写作——不存在真值。开放式领域的 PRM 要么不存在，要么是容易被"古德哈特定律"攻击的学习模型。这将并行搜索的适用范围限制在可验证领域。

**2. 延迟 vs 质量。** 思考 token 增加与思考长度成正比的延迟。在回答前思考 8,000 个 token 的模型，响应时间比直接回答模型长 8–20 倍。对于对话式或交互式应用，这通常是不可接受的。自适应计算（根据查询难度决定思考多少）是正确的工程答案，但需要一个好的难度分类器，而这本身就非平凡。

**3. 训练计算量与推理计算量的可替代性。** Snell 等证明，最优推理策略下的 70B 模型在 MATH 上可以媲美 GPT-4。但这并不意味着推理计算量完全替代训练计算量——70B 模型仍然需要见过足够多的数学知识，才能以合理概率生成正确的推理链。低于某个训练阈值，再多的推理计算量都无法弥补差距。

对从业者而言：若任务可验证（数学、代码、带真值验证的结构化提取），在寻求更大模型之前，先尝试 PRM 引导的 Best-of-N。若任务需要模型单次无法完成的多跳推理，用 GRPO 微调或使用预训练思考模型。若任务是开放式的，推理时扩展目前尚无成熟方案——这是开放研究领域。
