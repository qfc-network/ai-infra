# Qwen3

- **作者 / 机构**: 通义千问团队，阿里云
- **发表时间**: 2025-04
- **链接**: [Qwen3 博客](https://qwenlm.github.io/blog/qwen3/) · [HuggingFace 合集](https://huggingface.co/collections/Qwen/qwen3-67dd247413c7f01c2f5ed641)

## TL;DR

Qwen3 是阿里巴巴最强大的开放权重模型系列，于 2025 年 4 月发布。规模从 0.6B 到 235B 参数不等，引入了一个关键的 serving 设计决策：**思考/非思考切换**——无需两套独立权重，即可在推理时在完整思维链推理模式和直接回答模式之间切换。旗舰版 **Qwen3-235B-A22B** 是一个 MoE 模型，总参数 235B，每个 token 激活 22B，在主要基准测试上超越 GPT-4o 和 Claude 3.7 Sonnet，且 serving 计算量约为具有同等能力稠密模型的一半。稠密变体（Qwen3-32B 至 0.6B）覆盖 MoE 不适用的部署场景。本文聚焦基础设施含义：思考切换机制、MoE 架构选择，以及如何针对实际部署构建模型系列。

## 背景与动机

Qwen2.5（2024 年底）确立了阿里巴巴作为开放权重竞争者的地位：强大的多语言覆盖、有竞争力的代码和数学能力，以及丰富的规模选择。Qwen3 在此基础上进行了两项结构性改变：

1. **思考模式**：受 DeepSeek-R1 成功启发，Qwen3 将通过思维链推理作为原生能力。Qwen3 不是训练独立的"思考"和"聊天"模型，而是训练一个可通过软开关在两种模式下运行的单一模型。

2. **顶层 MoE**：Qwen3-235B-A22B 沿袭 DeepSeek V3 和 Llama 4 建立的模式——大型稀疏模型，serving 代价由激活参数（22B）而非总参数（235B）决定。

综合结果：一个可在推理任务上匹配前沿质量的模型，同时可部署在硬件需求仅为同等能力稠密模型三分之一的环境中。

## 思考/非思考切换

### 机制

Qwen3 同时在思维链推理（思考）和直接回答（非思考）数据上训练。切换通过**系统提示词**或 API 标志在推理时控制，而非使用独立的模型权重。

- **思考模式**（`enable_thinking=True`）：模型在最终回答前生成内部的 `<think>...</think>` 块。思考 token 不向用户展示（或以可折叠块展示，取决于应用）。这等同于 [DeepSeek-R1](../../deepseek/r1/zh.md) 中的推理轨迹模式和[推理时扩展](../../foundational/inference-time-scaling/zh.md)中描述的测试时计算量扩展。

- **非思考模式**（`enable_thinking=False`）：模型直接产生回答，不生成 `<think>` 块。延迟和成本显著降低——不生成推理 token。

### 训练含义

为了让同一权重支持两种模式，模型分多阶段训练：

1. **长 CoT 冷启动**：在精心策划的思维链轨迹上微调，建立推理能力。
2. **推理 RL**：GRPO 式强化学习，采用基于规则的奖励（可验证答案：数学、代码）——与 [R1](../../deepseek/r1/zh.md) 相同的方案。
3. **模式融合**：进一步的 SFT 和 RL，使模型在思考和非思考模式间干净切换，确保禁用思考模式不会降低非推理任务的性能。

第 3 阶段的关键挑战：思考模式需要长输出（推理轨迹可能有数千 token）；非思考模式需要简短直接的输出。训练一个模型同时做好两件事需要精心的数据混合和奖励设计，以防止模式坍塌。

### Serving 含义

切换对基础设施有直接影响：

- **KV cache 大小**：在思考模式下，KV cache 必须容纳推理轨迹（可能数千 token）后才能开始回答。非思考模式有标准 KV cache 需求。
- **TTFT vs 吞吐量权衡**：思考模式 TTFT 高（必须生成完整推理轨迹后才能开始回答）；非思考模式 TTFT 低。Serving 基础设施必须在同一部署中同时支持两种模式。
- **成本核算**：部分服务商对思考 token 收费；另一些则隐藏。相同最终回答长度下，思考模式请求的实际计算成本是非思考模式的 3–10 倍。

## MoE 架构：Qwen3-235B-A22B

### 设计选择

Qwen3 的 MoE 沿袭 [DeepSeekMoE](../../deepseek/moe/zh.md) 建立并在 V3 中精炼的模式：

- **细粒度专家**：每个专家比粗粒度设计（如 Mixtral 的 8 个大专家）更小，总专家数更多。235B / 22B 激活意味着约 10× 的扩展比。
- **top-K 路由**：K > 1 的 top-K 提供冗余——被一个专家服务不佳的 token 可由第二个专家部分补偿。与 Llama 4 的 top-1 不同，Qwen3 使用 top-2+ 路由。
- **无共享专家**（与 DeepSeekMoE 不同）：路由完全动态；没有始终激活的 FFN。

相对于稠密模型的权衡与任何 MoE 相同：更低的 serving 计算（22B 激活）、更高的总内存需求（235B 参数）、每个 MoE 层需要额外的专家并行 all-to-all 通信。

### 稠密变体

对于 MoE 不适用的场景（单 GPU 部署、缺乏专家并行基础设施），Qwen3 提供稠密变体：32B、14B、8B、4B、1.7B、0.6B。所有变体均支持思考/非思考切换。

32B 稠密变体是一个值得关注的节点：它以不到一半的参数量超越了 Qwen2.5-72B（上一代旗舰），反映了基于 RL 的后训练带来的收益。

## 架构细节

Qwen3 系列通用：

- **注意力**：全系列使用 GQA。
- **位置编码**：RoPE + 基于 YaRN 的长上下文扩展。
- **上下文长度**：大多数变体基础 32k，通过 YaRN 缩放扩展至 128k；MoE 变体通过额外位置插值支持 100 万 token。
- **词表**：151,936 个 token（继承自 Qwen2.5，覆盖约 30 种语言）。
- **归一化**：RMSNorm 前归一化，与 Llama 3 / Qwen2.5 相同。

除 MoE 结构和思考切换外无架构创新——价值在于训练方案。

## 训练方案要点

### 数据

Qwen3 在约 36T token 上训练（Qwen3-235B）。数据质量经过严格过滤：

- 多阶段质量评分（语言模型困惑度过滤、基于规则的启发式方法、基于分类器的过滤）。
- 更强模型生成的合成数据，用于数学、代码和推理。
- 强多语言覆盖：中文和英文为主；约 30 种其他语言。

### 后训练

后训练流程是区别于 Qwen2.5 的关键：

1. **多样任务 SFT**（指令跟随、编码、数学、多语言）。
2. **长 CoT SFT** 用于推理能力冷启动。
3. **可验证奖励 RL**（GRPO；与 DeepSeek-R1 相同模式）。
4. **模式融合 SFT + RL** 以稳定思考/非思考切换。
5. **最终 DPO 通道** 用于回答风格和安全性。

RL 阶段负责最大的质量提升——与[推理时扩展](../../foundational/inference-time-scaling/zh.md)的论点一致：推理能力通过 RL 驱动的思维链获得比单纯的预训练规模扩展更高效。

## 工程权衡

| 决策 | 收益 | 代价 |
|---|---|---|
| 单模型思考切换 | 两种模式共用一套权重；部署更简单 | 训练复杂度高；后训练期间模式坍塌风险 |
| MoE 235B/22A | 22B 模型的 serving 代价；235B 模型的质量 | 需要专家并行基础设施；总权重存储量大 |
| 细粒度 top-2 路由 | 冗余；更平滑的损失曲面 | 每层 2× all-to-all（vs top-1） |
| 稠密变体（32B–0.6B） | 宽广的部署范围；无需 EP 基础设施 | 同等质量下 serving 计算高于 MoE |
| 128k–100 万上下文（via YaRN） | 开箱即用的长上下文能力 | YaRN 插值在中等上下文范围略有退化；KV cache 线性增长 |
| 重 RL 后训练 | 大幅推理质量提升；数学/代码基准 | RL 不稳定性风险；可验证基准上的奖励黑客风险 |

## 基准表现（2025 年 4 月）

Qwen3-235B-A22B 在主要推理基准上：

- **AIME 2024**：思考模式下约 85% pass@1（与 o1 级别模型竞争）。
- **LiveCodeBench**：开放权重前三。
- **MMLU-Pro, GPQA**：与 GPT-4o 竞争。

Qwen3-32B（稠密）：在许多基准上与 Qwen2.5-72B 和 Llama 3 405B 竞争，但仅有 32B 参数。

这些数字结合 serving 计算来看最有意义：Qwen3-235B-A22B 以每 token 22B 激活参数取得前沿结果，显著低于具有同等能力的稠密模型。

## 深度解析

Qwen3 的思考切换对推理基础设施而言是最具操作意义的方面。它承认推理能力和直接回答能力最好由不同的推理策略服务——但运营简单性强烈支持单套权重。训练一个模型在不发生模式坍塌的情况下两者兼顾的技术挑战不小；Qwen3 的公开发布表明，通过精心的 RL 后训练这是可行的。

对于在 Qwen3-235B-A22B 和 Llama 4 Maverick 之间选择的团队：两者的 MoE 成本结构相似（均约 17–22B 激活），但 Qwen3 有更强的多语言覆盖和更成熟的 RL 后训练流程；Llama 4 有原生多模态能力和更好的长上下文架构（iRoPE vs YaRN）。选择在很大程度上取决于使用场景。

32B 稠密变体是大多数没有专家并行基础设施的部署的实际默认选择——BF16 下可运行在 2 × 80 GB GPU 上，支持思考模式，质量匹配上一代 70B+ 模型。
